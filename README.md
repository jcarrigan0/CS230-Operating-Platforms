# CS230-Operating-Platforms

# Q and A

Q: Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?

A: The Gaming Room is a game company that wants to develop a web based game based on the 1980s television game Win, Lose or Draw. They wanted CTS to design a web-based version of their game that could support multiple teams and players while being accessible across different operating platforms. The software also needed to maintain unique game, team, and player names and use a client-server architecture to manage the game state.

Q: What did you do particularly well in developing this documentation?

A: I believe I provided a thorough operating platform evaluation based on the needs of the client. I identified the strengths and weaknesses of each platform and gave the client a clear picture of what each path forward would entail.

Q: What about the process of working through a design document did you find helpful when developing the code?

A: Using a design document helps break the large task into smaller, more manageable tasks. This design document helped me keep everything organized and allowed me to focus on each section that needed my attention throughout the process.

Q: If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

A: I believe the summary and requirements sections could have used more detail. If I were to revise the document, I would expand these sections to provide more context about the client's goals and how the individual software requirements relate to those goals. However, I would still try to keep these sections brief enough that the important information is easy to identify.

Q: How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?

A: I considered each user need in the context of software design. For example, for the need regarding uniqueness in game, team, and player names, I considered what kind of code design would be needed to accomplish this goal. It's important to consider this when designing because it prevents you from having to go back and alter previous code as you attempt to implement user needs in the later stages. 

Q: How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?

A: I approached designing the software by first identifying the client's requirements and then determining how each requirement would affect the overall design. From there, I broke the application into smaller components and considered what architecture, operating platform, and design patterns would best meet those requirements. In the future, I would use a similar approach by first analyzing the client's needs, breaking the project into manageable sections, and comparing different solutions before beginning development.
